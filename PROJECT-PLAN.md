# Grovance — Demo Application Build Plan

## 0. The Core Idea (read this first)

This app isn't just a product for clients — it's a **living sales pitch**. Every service
Grovance sells (automation, AI, end-to-end maintenance) should be *visibly running inside
the app itself*, with small callouts that say so. Examples of "dogfooding" you'll see
baked into the plan below:

- A dashboard stat updates → a small badge: "⚡ Auto-generated by Grovance Automation"
- The support widget is answered by a live AI assistant, not a static FAQ
- A "System Health / Maintenance" page shows real uptime, last deploy, next scheduled
  maintenance — proving the "end-to-end maintenance" promise is real, not a slide

This turns the demo into proof, not a pitch deck.

## 1. Tech Stack (as built)

**Updated:** switched from Next.js to a fully decoupled React + Express architecture —
this actually strengthens the pitch, since it lets you show clients "we built and manage
your entire backend infrastructure," separate from the storefront itself.

| Layer | Choice | Why |
|---|---|---|
| Frontend | **React 18 + Vite + TypeScript + Tailwind CSS v4 + React Router** | Fast dev loop, no server required to host it, deploys as static files anywhere |
| Backend | **Node.js + Express + TypeScript** (standalone API, own repo folder) | Fully decoupled from the frontend — a real, separately deployable service |
| Data layer | **In-memory store now** (`backend/src/lib/store.ts`), designed as a thin adapter → swap to **PostgreSQL** (via `pg` or Prisma) with zero route changes when you're ready for a persistent client | Kept the sandbox scaffold dependency-light and fast to run; the interface is already DB-shaped |
| AI | **Anthropic Claude API** (`@anthropic-ai/sdk`) called server-side only | Powers the embedded assistant and content generator; key never touches the frontend |
| Automation engine | **node-cron jobs in the backend** + an activity log every job writes to | Visible, explainable automation — the frontend reads this same log live |
| Hosting | Frontend → **Vercel/Netlify** (static). Backend → **Render/Railway/Fly.io** | Split hosting matches the split architecture; each scales independently |
| Repo/CI | **GitHub + GitHub Actions** | Lets you show clients an actual CI pipeline (proof of "maintenance") |

This stack lets you ship a genuinely working v1 in days, not months, and everything in it
is production-grade — nothing here is throwaway "demo code."

## 3. Feature Modules Mapped to Your Services

### A. Automation (visible, explainable, not a black box)
- **Workflow Builder (simplified):** if-this-then-that rules clients can toggle
  (e.g., "low stock → notify owner", "new order → send confirmation email")
- Every automated action logs to an **Activity Feed** with a small ⚡ icon and timestamp,
  so the client *sees* automation happening in real time
- Scheduled jobs (cron) for: daily sales summary, weekly backup confirmation, inventory
  reminders

### B. AI (client-requirement driven, not generic chatbot)
- **Embedded AI Assistant** (Claude-powered) trained on that client's FAQs/products —
  answers customer questions on their storefront
- **Content Studio**: generates product descriptions, promo captions, reply drafts
- **Insights Engine**: turns raw numbers into a plain-language weekly report
- Because AI needs are "based on client requirement," structure this as a **pluggable
  AI-module system** — each client's portal can have different AI features toggled on,
  which itself becomes a sales conversation ("what would you like AI to help with?")

### C. End-to-End Maintenance (the trust layer)
- **/maintenance page**: real uptime %, last deployment timestamp (pull from Vercel API
  or a simple deploy-log table), open/closed support tickets
- **Support ticket system**: client submits an issue → status tracked → resolved-by and
  time-to-resolution shown (this is your proof of SLA)
- **Changelog widget**: "What we improved for you this week" — auto-populated from
  your GitHub commit/PR history via GitHub API

## 4. Build Phases

**Phase 0 — Branding** ✅ done (logo above)

**Phase 1 — Foundation (2–3 days)**
- Repo scaffold, Next.js + Tailwind + shadcn/ui, Prisma schema, Supabase project, auth flow
- CI pipeline (lint + build on PR) — this alone is a small "maintenance" trust signal

**Phase 2 — Public Marketing Site (2–3 days)**
- Landing page with logo, services, and a **live mini-demo** embedded (e.g., a working
  AI chat box right on the homepage that visitors can try)

**Phase 3 — Client Portal Shell (3–4 days)**
- Dashboard, navigation, multi-tenant structure (each client = a workspace)

**Phase 4 — Automation Center (3–4 days)**
- Rule toggles, cron jobs, activity feed

**Phase 5 — AI Modules (4–5 days)**
- Assistant, content studio, insights — all calling the Claude API server-side

**Phase 6 — Maintenance & Trust Layer (2–3 days)**
- Uptime/status page, ticketing, changelog feed

**Phase 7 — Polish & Client Handoff Demo Script (1–2 days)**
- Seed realistic demo data for a fictional "local shop" so every prospect sees a
  populated, believable workspace, not an empty dashboard
